# 背景・作成の経緯・設計思想 (Background & Motivation)

## 1. すべてのはじまり：「端末の文字化け」と「アプリの安全性」

本プロジェクト（`BG02 Studio`）は、Bluetooth 対応の電子缶バッジ **BG02 (E-BADGE)** をより安全かつ実用的に使いたいという純粋な動機から始まりました。

### 抱えていた 2 つの課題
1. **端末側設定画面の日本語文字欠け・文字化け**  
   `BG02` 本体の設定画面では言語切り替え機能があり「日本語」を選択できます。しかし実際には、翻訳が不自然なだけでなく**文字が抜け落ちて表示されない箇所**が存在し、そのままでは非常に使いづらい状態でした。  
   当初は「フォントデータだけを日本語完全対応のものに差し替えられないか」「ファームウェアを書き換えられないか」と模索したのが出発点です。
2. **公式アプリへのセキュリティ・プライバシー面の不安**  
   公式提供の Android アプリ（`com.legend.smartwatch.electronicbadge.android`）には、電子バッジへ画像を送るだけの用途としては過大な権限（精密な位置情報、連絡先読み取り、マイク録音、カメラ、通知アクセス、外部ネットワーク通信および位置情報 SDK など）が含まれており、普段使いのスマートフォンへインストールし続けることに不安がありました。

## 2. 調査を通じて見えてきた現実と発想の転換

### 2.1 `openfantasymap/badger` との互換性調査
当初、電子バッジ向け OSS として知られる `openfantasymap/badger`（旧 `baji` プロトコル、`PRODUCT_ID = 0x25`・文字/アイコンビットマップ描画系）の流用を検討しました。  
しかし実機 `BG02` でテストしたところ通信が成立せず、プロトコルを解析した結果、`BG02` は **`mywatchsdklib` / `WatchTheme3` 系プロトコル**（GATT UUID `7e400001-...`、接続時 `0x12/0x0A` ペアリング、Notify 購読、受信毎の `0xDC` ACK 必須）を採用しており、プロトコル層から非互換であることが確認されました。

### 2.2 ファームウェア改変の評価と断念
端末情報およびコンパニオン APK の調査から、以下を確認しました。
- OTA・認証処理ではアプリ内の暗号署名検証・鍵交換ロジックが関与しており、署名済でないカスタム FW の書き込みは安全に行えません。
- オリジナル FW イメージや文鎮化（Brick）からの復旧手段（ブートローダ操作・テストパッド仕様）が存在しません。
- 一方で、画面のカスタム表示（`WatchTheme3`）は**アプリ側で生成した Baseline JPEG 画像を直接送信・描画する方式**であり、端末内蔵フォント ROM を経由しません。したがって **「カスタム表示画面の日本語文字欠けは画像側へ美しいフォントを焼き込むことで解決でき、本体設定メニューの文字化け自体は変更しない」** という棲み分けを前提としています。

### 2.3 「簡易文字描画ツール」から「円形画像合成スタジオ」へ
初期の解析用プロトタイプ（ワークスペース内の解析用 HTML/JS 版）では、テキストをそのまま描画して送る実験も行いました。しかしフォント置換自体ができない以上、単純な文字描画だけでは本来の「端末UI改善」の代替にはなりにくく、電子缶バッジ本来の魅力を活かすには方向転換が必要でした。

そこで行き着いたのが、本 PWA の中核コンセプトです：

- **お気に入りの画像を選び、バッジの「円形枠（240×240）」に対して直感的に位置合わせ・拡大縮小・回転ができること**
- **その上で、必要であれば画像の上に文字（イベント名、ハンドルネーム、肩書きなど）を美しい日本語フォントで綺麗に合成できること**
- **個人情報や外部通信を一切使わないクリーンな TypeScript製 PWA として、誰でも GitHub Pages 等から安全に使えること**

## 3. 大切にしている実装上のポリシー

- **後から見て「なぜ」がすべて分かること**  
  BLE のパケットサイズ（20 バイト）、接続維持の順番、JPEG のサイズとタイムアウトの関係など、実機テストで苦労して掴んだノウハウがコードから失われないよう、**全クラス・関数・変数・定数への TypeDoc 記述**と**意図・経緯コメント**を徹底します。
- **わからない仕様を勝手に推測で実装しないこと**  
  実機未検証の機能（動画 AVI 転送や一覧取得 `0x20/0x03` 等）は推測で本番機能へ混ぜ込まず、確証が取れた範囲から段階的に積み上げます。
